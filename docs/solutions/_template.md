# Replace with a clear solution title

## Problem

Describe the real problem that happened.

Keep this concrete.

## Context

Explain the system context that mattered:

- service or subsystem
- scale or traffic shape
- relevant stack details
- operational constraints

## Root Cause

Explain what actually caused the problem.

If the root cause was uncertain at first, note that briefly.

## Solution

Explain what was changed or introduced.

Use short subsections if needed, but keep the writeup readable.

## Tradeoffs

Explain what you accepted or chose not to optimize.

## Verification

List how the solution was checked.

Examples:

- tests added
- metrics observed
- rollout checks
- incident did not recur

## Reuse Guidance

Explain when someone should reuse this approach.

## Do Not Reuse When

Explain when this solution would be the wrong fit.

## Follow-Up

List any useful next steps, cleanup, or future improvements.
